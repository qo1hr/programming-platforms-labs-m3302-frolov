# Лабораторная работа 3. Статическая и динамическая библиотеки

Среда: Linux x86-64, GCC/G++ 14.2.0, GNU binutils 2.44 (контейнер Alpine). Все артефакты этой папки пересобраны для Linux.

## Этап 1. Статическая библиотека

```sh
gcc -c vector_math.c -o vector_math_static.o
ar rcs libmath_static.a vector_math_static.o
g++ -c main.cpp -o main_lab3.o
g++ main_lab3.o -L. -lmath_static -o app_static
./app_static
```

Вывод:

```text
Library version: v2.4.1-release
Dot product result: 32
```

`ar`: `r` добавляет или заменяет одноимённый член, `c` создаёт архив без предупреждения, `s` строит индекс символов. Повторный запуск заменяет член архива с тем же именем. `nm main_lab3.o` показывает `T main`: имя точки входа программы не искажается C++ name mangling. Ссылки на библиотеку имеют имена `U dot_product` и `U get_lib_version` благодаря `extern "C"`.

## Этап 2. Динамическая библиотека

```sh
gcc -c vector_math.c -o vector_math_nopic.o
gcc -shared -o libmath_broken.so vector_math_nopic.o
gcc -c -fPIC vector_math.c -o vector_math_pic.o
gcc -shared -o libmath_dynamic.so vector_math_pic.o
g++ main_lab3.o -L. -lmath_dynamic -Wl,-rpath,'$ORIGIN' -o app_dynamic
./app_dynamic
```

Сборка **без** `-fPIC` в данной версии GCC/binutils завершилась с кодом 0 и без сообщения об ошибке. Поэтому `libmath_broken.so` существует: для конкретного кода использованы релокации, с которыми линкер справился. Утверждение задания об обязательной ошибке не является универсальным. `-fPIC` применён в рабочей версии. `rpath=$ORIGIN` позволяет загрузчику найти `.so` рядом с программой после переноса папки.

`app_dynamic` вывел те же две строки, что и статическая версия. `size`:

```text
   text   data    bss    dec    hex filename
   2303    608    368   3279    ccf app_static
   2252    648    368   3268    cc4 app_dynamic
```

Сегмент `text` динамической программы меньше на 51 байт в этой сборке. Код `dot_product` и `get_lib_version` находится в `libmath_dynamic.so`, а исполняемый файл хранит обращения к библиотеке.

## Этап 3. Порядок компоновки

```sh
g++ -L. -lmath_dynamic main_lab3.o -o app_wrong_order
g++ main_lab3.o -L. -lmath_dynamic -Wl,-rpath,'$ORIGIN' -o app_dynamic
```

Первая команда завершилась с кодом 1. Линкер сообщил `undefined reference to 'get_lib_version'` и `undefined reference to 'dot_product'`. В начале сканирования множество неразрешённых символов `U` пусто; при раннем просмотре библиотеки её определения не выбираются. После чтения `main_lab3.o` ссылки попадают в `U`, но библиотека уже пройдена. При правильном порядке `U` заполняется объектным файлом до обработки библиотеки, её определения `D` разрешают ссылки; для статического архива нужный объект попадает в множество извлечённых файлов `E`.

## Этап 4. Name mangling

Для опыта копия заголовка без блоков `extern "C"` использовалась только во временной директории, рабочий заголовок сохранён. `nm` C++ объекта без этого блока показал:

```text
U _Z11dot_productPKiS0_i
U _Z15get_lib_versionv
```

`nm -D libmath_dynamic.so` показал экспортируемые имена `dot_product` и `get_lib_version`. Линковка без `extern "C"` завершилась с кодом 1 и ошибками `undefined reference to 'get_lib_version()'` и `undefined reference to 'dot_product(int const*, int const*, int)'`.

## Подготовленный исходный код

`vector_math.h`:

```c
#ifndef VECTOR_MATH_H
#define VECTOR_MATH_H

#ifdef __cplusplus
extern "C" {
#endif

extern const char* get_lib_version(void);
int dot_product(const int* a, const int* b, int n);

#ifdef __cplusplus
}
#endif

#endif
```

`vector_math.c`:

```c
#include "vector_math.h"

static const char* LIB_VERSION = "v2.4.1-release";

const char* get_lib_version(void) {
    return LIB_VERSION;
}

int dot_product(const int* a, const int* b, int n) {
    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum += a[i] * b[i];
    }
    return sum;
}
```

`main.cpp`:

```cpp
#include <cstdio>
#include <iostream>
#include "vector_math.h"

int main() {
    int v1[] = {1, 2, 3};
    int v2[] = {4, 5, 6};

    std::cout << "Library version: " << get_lib_version() << std::endl;
    std::cout << "Dot product result: " << dot_product(v1, v2, 3) << std::endl;

    return 0;
}
```
