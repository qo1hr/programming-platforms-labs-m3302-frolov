# Лабораторная работа 1. Этапы сборки и наследие

Среда: Linux x86-64, GCC/G++ 14.2.0 (контейнер Alpine). Исходники и результаты команд находятся в этой папке.

## Задача A. Do It Yourself

1. `wc -l simple.cpp simple.i` дал 23 и 400 строк соответственно.
2. Перед `main` в `simple.i` расположены объявления из `<cstdio>` и системных заголовков, а также маркеры исходных файлов. Препроцессор вставил содержимое заголовков. `main` начинается около строки 395.
3. Литерал остался в вызове `printf` на строке 398: `printf("Result: %d, Counter: %d, Magic: %d\n", result, global_counter, MAGIC);`. Препроцессор не изменил его содержимое.
4. `wc -c simple_O0.s simple_O2.s`: 2268 и 1445 байт. Листинг `-O2` короче в 1,57 раза.
5. В `simple_O0.s` функция `_Z6squarei` (C++ имя `square`) использует `mov eax, DWORD PTR -4[rbp]` и `imul eax, eax`.
6. Перед вызовом `_Z14sum_of_squaresii` в `main` стоят `mov esi, 4` и `mov edi, 3`. В x86-64 System V ABI первые два целочисленных аргумента передаются через `edi` и `esi`.
7. В этом конкретном `-O2` листинге отдельная `square` **осталась**, но вызов из `main` исчез: компилятор вычислил `sum_of_squares(3, 4)` как 25 при компиляции. Поэтому предположение задания об исчезновении самой функции здесь не подтвердилось.
8. `nm simple.o` показывает `0000000000000000 r _ZL5MAGIC`: малая `r` означает локальный символ в read-only данных. Константа не должна изменяться и имеет внутреннее связывание.
9. `size simple.o` показывает `text=400`, `data=0`, `bss=4`, `dec=404`, `hex=194`. В `text` находятся код и данные только для чтения; `bss` — неинициализированный `global_counter`. Нули BSS не записываются в файл целиком.
10. `./simple_app` вывел `Result: 25, Counter: 1, Magic: 42`.

Команды:

```sh
g++ -E simple.cpp -o simple.i
g++ -S -masm=intel -O0 simple.cpp -o simple_O0.s
g++ -S -masm=intel -O2 simple.cpp -o simple_O2.s
g++ -c simple.cpp -o simple.o
nm simple.o
size simple.o
g++ simple.o -o simple_app
./simple_app
```

Код `simple.cpp`:

```cpp
#include <cstdio>

int global_counter = 0;
const int MAGIC = 42;

int square(int x) {
    return x * x;
}

int sum_of_squares(int a, int b) {
    return square(a) + square(b);
}

void bump_counter() {
    global_counter++;
}

int main() {
    int result = sum_of_squares(3, 4);
    bump_counter();
    printf("Result: %d, Counter: %d, Magic: %d\n", result, global_counter, MAGIC);
    return 0;
}
```

## Задача B. Наследие

Исходный `legacy.c` собран командой `gcc -std=gnu99 -Wno-error=implicit-int legacy.c -o legacy_app`. Режим совместимости нужен из-за старого неявного `int`. Программа читает строку из stdin и возвращает код 0 при правильном вводе. Анализ построенного в ней массива и обратное применение преобразований дали:

```text
flag{i_considered_giving_only_the_binary_24412707}
```

Проверка: передача этой строки в `legacy_app` завершилась с кодом 0; `test` — с кодом 1. Токен `FLAG{b1nary_4rch4eology_2026}` относится к `core.o` из ЛР 2 и не является ответом этой задачи.

Восстановленный читаемый исходник `recovered.c`:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char input[1024];
    if (!fgets(input, sizeof input, stdin)) {
        return 1;
    }
    return strcmp(input, "flag{i_considered_giving_only_the_binary_24412707}\n") == 0 ? 0 : 1;
}
```

`recovered.c` собран в `recovered_app`. С правильной строкой он возвращает 0, с другой — 1.
